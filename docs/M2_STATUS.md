# 🧠 M2 Status — AI Core & Skills (DraftMate Studio)

> Handoff for M1 / M3 / M4. Generated by `setup_backend_m2.sh`.

## ✅ What is done
| Piece | File | Notes |
|---|---|---|
| LLM Gateway (Claude / GPT / Gemini) | `backend/core/llm_gateway.py` | Streaming, lazy SDK imports, auto-fallback to any keyed provider, **offline placeholder mode when no key** |
| Skill Engine | `backend/core/skill_engine.py` | YAML loader with **hot reload**, heuristic + LLM router, chaining (`"a+b"`), prompt builder with hard anti-hallucination rules |
| Style Profiler | `backend/core/style_profiler.py` | `profile(markdown)` → StyleProfile (camelCase, matches `types.ts`), `style_card()` for prompts. LLM + heuristic fallback, cached |
| Context bridge | `backend/core/context_bridge.py` | Uses M3's `context_manager.build_context` if present, else naive retrieval. Produces the `usage` numbers |
| Doc store (seam) | `backend/core/doc_store.py` | In-memory; M4's upload saves docs here |
| 10 skills | `skills/*.yaml` | legal_notice, contract_drafting, agreement, petition, contract_review, redlining, due_diligence, legal_research, case_analysis, summarisation |
| Endpoints | `backend/api/*.py` | `GET /api/skills`, `POST /api/route`, `POST /api/draft` (SSE), `POST /api/edit`, + helpers `GET /api/models`, `POST /api/skills/reload`, `POST /api/style/profile` |
| Tests | `backend/tests/test_m2.py` | Offline, no keys needed: `cd backend && pytest -q` |

## 🔌 Integration instructions

**M4 (backend skeleton, upload):**
- `backend/main.py` exists already (M2 created the first skeleton: CORS + `/api/health` + M2 router). It is **yours** now; add your routers where the TODOs are.
- In `POST /api/upload`, after MarkItDown → Markdown:
  ```python
  from core import doc_store, style_profiler
  style = await style_profiler.profile(markdown)          # → {tone,structure,terminology[],clausePatterns[],formatting}
  doc_store.save(doc_id, filename, markdown, style, tokens)
  ```
  and return `{id, name, size, tokens, style}` as the contract says. `/api/draft` then picks the docs up via `doc_ids`.
- Merge `backend/requirements.txt` (M2 appended its packages; add MarkItDown, python-docx, reportlab, …).

**M3 (verification & context):**
- Drafts contain `[CITE: …]` markers for every authority; one authority per marker, no `]` inside. Your extractor can rely on that (and still run regex as a safety net).
- To plug in your retriever, create `backend/core/context_manager.py` with `build_context(instruction: str, doc_ids: list[str]) -> {"text": str, "raw": int, "sent": int}` (sync or async). `raw` = tokens of full docs, `sent` = tokens of the retrieved text. M2 picks it up automatically and adds system/instruction tokens on both sides. Read docs from `core.doc_store.many(doc_ids)` (`markdown` field).
- The prompt tells the model to write `[No authority available — advocate to supply]` instead of guessing — treat that string as "needs a human".

**M1 (frontend):** nothing to change. Notes:
- `/api/route` returns `skill_id` **only when confident**; otherwise the skill chosen in the Library (`activeSkillId`) is used. 
- Unknown SSE event types are ignored by the UI, so more can be added later.
- `/api/edit` **rejects** edits that alter citation spans and returns the original HTML with an explanatory `summary` (shown in the toast).

## 🧩 Adding a skill live (demo moment)
Drop a `*.yaml` in `/skills` (copy any existing one; required keys: `id`, `name`, `system_prompt`). The next `GET /api/skills` (UI reload) shows it — no restart. Invalid YAML is skipped with a warning, never crashes the server.

Chaining: send `skill_id: "legal_research+legal_notice"` → research runs silently, its notes feed the notice, only the notice streams.

## ⚠️ Known limitations / honest notes
- Model IDs are env-overridable (`CLAUDE_MODEL`, `GPT_MODEL`, `GEMINI_MODEL`). If a provider rejects a name, change it in `.env` — no code change.
- Without any API key the server streams a clearly labelled **offline placeholder** (not a real draft). `GET /api/models` shows `offline_mode`.
- Token numbers use a ~4 chars/token estimate unless M3's context manager supplies exact counts.
- Edit via LLM preserves citation spans by validation, not by guarantee; the original is kept on any mismatch.
- Voice `activate_skill` intent (README §8) is not in the frontend `Intent` type; "use the X skill" is handled as a draft with that skill.
- Prompts are written but not yet tuned against real model output — **needs 30–60 min of real-key testing** per skill (M2 next step).
